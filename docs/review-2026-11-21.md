## 3. Inventory

### 3.1 Publishing (“CMS”)

There is no custom CMS, no admin UI, no user table, and no session.

Publishing is a git commit plus a Dokploy deploy:

1. Add `content/essays/<slug>.html`. The sampled essay is a fragment: article header, inline SVG figures, `<article class="prose">`, a notes list, a `form[data-sub]` subscribe block, and prev/next links.
2. Add one entry to `ALL_ESSAYS` in `lib/essays.ts`: `slug`, `title`, ISO `date`, `read`, `cat`, `card`, `meta`.
3. `ESSAYS` is that array sorted newest-first. Sitemap, RSS, `/llms.txt`, the writing index, and essay `<head>` metadata are generated from it.
4. `app/writing/[slug]/page.tsx` reads the HTML at build time and injects it. `dynamicParams = false`, so a slug that is not in the array 404s.
5. There is no draft flag. An entry in the array is published on the next deploy.

**Storage.** Essay HTML is in git. The only database table is `subscribers` (see schema below). Resend holds the audience that broadcasts go to. Postgres is the app’s copy of that list.

**Auth.** None. Anyone who can push `main` and anyone who can deploy in Dokploy can publish.

**Gaps**

- No preview, draft, or scheduled publish. Future dates still ship if they are in the array.
- Two subscribe implementations: `components/SubscribeForm.tsx` (React) and, inside essay HTML, `form[data-sub]` handled by `components/SiteScripts.tsx`. The essay path does not send the honeypot field.
- Table of contents only rewrites plain `<h2>text</h2>` inside `<article class="prose">`. An `<h2>` with a nested tag gets no id.
- `README.md` still says machine files are static in `public/` and that `.github/workflows/ci.yml` runs on push. The tree has no `.github` workflows. `rss.xml`, `sitemap.xml`, and `llms.txt` are generated. `AGENTS.md` is the accurate description; the README is stale.
- `lib/validation.ts` exports `checkoutSchema`. No route uses it.

### 3.3 Backend

**API**

| Method and path | Behaviour |
| --- | --- |
| `POST /api/subscribe` | JSON. Zod email (trim, lower-case, max 254) plus optional `source` (max 64) and honeypot `website`. Non-empty honeypot returns a fake success and writes nothing. Optional CleanTalk check. Then Resend audience add (best-effort), `INSERT … ON CONFLICT` into `subscribers`, then welcome email. DB failure is 500. Email failure is logged and the request still succeeds. |
| `POST /api/webhooks/resend` | Svix signature over the raw body, 5-minute timestamp window, `timingSafeEqual`. Handles `contact.updated`, `contact.deleted`, `email.complained`. Other types are acknowledged and ignored. |
| `GET /llms.txt`, `GET /rss.xml` | Force-static route handlers. |
| `GET` on `/api/subscribe` | Live response 405. |

**Schema** (`db/schema.sql`)

- Extension `citext`.
- `subscribers (id uuid pk, email citext unique, source text default 'unknown', status text default 'active', resend_contact_id text, created_at timestamptz, unsubscribed_at timestamptz)`.
- Indexes on `source` and `created_at desc`.
- No `CHECK` on `status`. No row-level security. The comment says that is deliberate: the app connects as its own role on a private network, replacing an older Supabase setup.
- Compose mounts the file into `docker-entrypoint-initdb.d`. Postgres runs that only on an empty data directory. Later schema edits are not applied by a migration tool. There is no migration history beyond this one file.

**Resend**

- `lib/resend.ts`: lazy client. If `RESEND_API_KEY` is unset, sends are skipped and logged. `addToAudience` no-ops without `RESEND_AUDIENCE_ID`.
- Welcome template: `emails/Welcome.tsx` (React Email). Default site URL `https://sujanbhuiyan.com`. The template has no unsubscribe link.
- Issue template: `emails/AIOperatorNewsletter.tsx`, plus a static HTML file `emails/the-ai-operator-email.html` described as something to paste into Resend.
- `scripts/send-broadcast.ts` (`pnpm newsletter`) creates a Resend broadcast draft. `SEND=1` sends it. `ISSUE` and `SUBJECT` override the label. This is a manual script, not a worker.

**Background jobs.** None in the app. No queue, no cron, no `middleware.ts`.

- `docker-compose.yml`: `web` depends on healthy `db` (Postgres 16 Alpine, user `sujan`, database `sujanbhuiyan`, named volume). Database port is not published. Web publishes `3000:3000`.

### 3.4 Security posture

**What is already solid**

- Security headers on `/:path*` and observed live: CSP, HSTS (`max-age=63072000; includeSubDomains; preload`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, a restrictive Permissions-Policy. `poweredByHeader: false`.
- CSP locks `frame-ancestors`, `object-src`, `base-uri`, `form-action`, and `connect-src 'self'`.
- Subscribe SQL is parameterized (`$1`…`$3`). Webhook updates are parameterized.
- Webhook verification uses the raw body, a 5-minute window, and a constant-time compare.
- Honeypot on the React form. Email is normalized and length-capped.
- Server-only DB and Resend modules. Secrets are not committed; ignore rules cover env files.
- Container runs as `nextjs`, not root. Compose does not publish Postgres.
- 404 is `noindex`. No admin surface to forget to protect.

**Findings**
